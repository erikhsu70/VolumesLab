# VolumesLab

CMS origin configuration and infrastructure migration status:
[migration runbook](docs/infrastructure-migration.md).

`/sitemap.xml` is generated by the server from the same CMS content and visibility
rules as the site. Live services in enabled sections, enabled indexable pages,
and blog posts are included automatically, without rebuilding. Redirects and
noindex pages are excluded. Responses can be cached for 60 seconds; CMS reads
use the site's existing fallback behavior during outages. `public/robots.txt`
advertises this endpoint. Do not add a static `public/sitemap.xml`, which would
override the dynamic response. Dates are omitted until reliable modification
dates are available for all content.

Schema.org JSON-LD is rendered on the server by `SiteChrome`, using the current
route's loader data and CMS-backed site data. Each successful page has one graph:
LocalBusiness, WebSite, the appropriate WebPage subtype, and breadcrumbs for
inner pages. Service pages add Service; articles add BlogPosting; the blog lists
its articles; FAQ and team pages describe their visible questions and people.
Redirects, unavailable pages and error responses do not receive page markup.
CMS text is escaped before embedding JSON in HTML. No ratings, unverified
prices, inferred modification dates or static opening hours are added.
